## 1. 文件结构与分层

`main.c` 由 STM32CubeMX 生成，用户代码全部写在 `USER CODE BEGIN/END` 区间内，重新 GENERATE CODE 不会被覆盖。

从下到上可以分成 4 层：

```
┌─────────────────────────────────────────┐
│ 命令层：main 循环 switch + UART 回调      │  字符 → 动作
├─────────────────────────────────────────┤
│ 运动层：Car_Forward/Backward/Turn/Stop   │  动作语义（前进/后退/转10°/停）
├─────────────────────────────────────────┤
│ 电机层：Motor_SetSpeeds/Left/Right       │  占空比 + 方向电平
├─────────────────────────────────────────┤
│ HAL 层：TIM3 PWM、GPIO、USART1 中断      │  CubeMX 生成
└─────────────────────────────────────────┘
```

这样分层的好处：

- 上层只关心“走/转/停”，不直接碰 CCR 和 IN1~IN4；
- 改速度、改转向时间只动宏定义或运动层；
- 换硬件（换引脚、换驱动）时主要改 CubeMX 和电机层，命令层不动。

## 2. 蓝牙接收与命令解析

### 2.1 外设与初始化

- USART1：**PA9 = TX，PA10 = RX，9600 8N1**，开启 USART1 全局中断；
- JDY-31 是蓝牙 3.0 SPP 透传模块，手机串口助手发什么，单片机就收什么；
- 初始化时启动**单字节中断接收**（[main.c:193-203](Core/Src/main.c#L193-L203)）：

```c
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_2);
Car_Stop();
HAL_UART_Receive_IT(&huart1, &rx_byte, 1U);
```

`HAL_UART_Receive_IT(..., 1)` 表示“只收 1 个字节，收完进回调”。每处理完一个字符再重新挂一次，形成“收一个 → 处理 → 再收一个”的节奏。

### 2.2 中断回调 `HAL_UART_RxCpltCallback`

实现见 [main.c:119-143](Core/Src/main.c#L119-L143)：

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART1)
  {
    char c = (char)rx_byte;

    if ((c >= 'A') && (c <= 'Z'))
    {
      c = (char)(c - 'A' + 'a');       /* 兼容大写字母 */
    }

    if ((c == 'w') || (c == 'a') || (c == 's') || (c == 'd') ||
        (c == 'z') || (c == 'x') || (c == 'c') ||
        (c == 'q') || (c == 'n') || (c == 'f'))
    {
      key_char  = c;
      key_ready = 1U;
    }

    if (key_ready == 0U)
    {
      (void)HAL_UART_Receive_IT(&huart1, &rx_byte, 1U);
    }
  }
}
```

逐句解释：

1. **判断是 USART1**：工程以后可能加第二个串口，先过滤；
2. **转小写**：手机键盘可能发大写 `W/A/S/D`，统一成小写后只维护一套判断；
3. **白名单过滤**：只认 `w a s d z x c q n f` 十个字符，其它字符（回车 `\r`、换行 `\n`、空格、乱码）直接丢弃；
4. **写入“邮箱”**：`key_char` 存字符，`key_ready` 置 1，告诉主循环“有一个命令待处理”；
5. **流控**：如果已经有一个命令待处理（`key_ready == 1`），就**不再重新挂接收**，等主循环处理完再挂。

### 2.3 为什么用单字符协议

早期版本用的是 `forward` / `backward` / `on` / `off` 这种多字符命令，需要：

- 字符缓冲区；
- 结束符判断（`\r`、`\n`、空格）；
- `strcmp` 比较；
- 防缓冲区溢出。

改成单字符后：

- **一个字符就是一个命令**，不需要组帧、不需要结束符；
- 不需要命令缓冲区，天然没有溢出问题；
- 手机串口助手即使自动追加 `\r\n`，也会被白名单过滤掉，不会误动作；
- 代码量和 RAM 占用都更小。

代价是可用的命令数量受单字符限制，但对这个遥控小车足够了。

### 2.4 接收流控：一个“单槽邮箱”（巧思）

`key_char + key_ready` 本质上是一个**深度为 1 的邮箱**：

```
收到字符 → key_char = c; key_ready = 1
                │
                ▼
        主循环取走并处理 → key_ready = 0 → 重新挂接收
```

这样设计的两个好处：

1. **不会覆盖正在处理的命令**：主循环处理命令期间（例如正在发回传字符串），接收是暂停的，新字符不会被写进 `key_char`；
2. **不需要环形缓冲区**：人手按键的速度远低于处理速度，深度 1 足够；即使连续快速发送，也只会丢后面的字符，不会破坏状态。

`key_ready` 和 `key_char` 都加了 `volatile`，因为它们在中断里写、主循环里读，防止编译器优化成寄存器缓存导致主循环看不到变化。

### 2.5 串口错误恢复

`HAL_UART_ErrorCallback`（[main.c:148-159](Core/Src/main.c#L148-L159)）：

```c
if (huart->Instance == USART1)
{
  __HAL_UART_CLEAR_OREFLAG(huart);
  if (key_ready == 0U)
  {
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1U);
  }
}
```

- 连续快速发送或线路干扰可能导致 **ORE 溢出**，如果不处理，HAL 的接收状态机会卡住，之后再也收不到数据；
- 这里清 ORE 标志并重新挂接收，相当于“自恢复”；
- 只有在没有待处理命令时才重新挂，避免和主循环重复挂接收。

### 2.6 主循环命令分发

主循环见 [main.c:207-290](Core/Src/main.c#L207-L290)，顺序很关键：

```c
while (1)
{
  /* ① 先处理转向超时 */
  if (turning && (int32_t)(HAL_GetTick() - turn_end_tick) >= 0)
  {
    if (car_dir == 0U) Car_Stop();
    else { turning = 0U; Motor_SetSpeed(speed_percent); }
  }

  /* ② 再处理待处理命令 */
  if (key_ready)
  {
    switch (key_char)
    {
      case 'w': Car_Forward();  UART_SendString("FWD\r\n");  break;
      case 's': Car_Backward(); UART_SendString("BACK\r\n"); break;
      case 'a': Car_Turn('a');  UART_SendString("LEFT\r\n"); break;
      case 'd': Car_Turn('d');  UART_SendString("RIGHT\r\n");break;
      case 'z': Car_SetSpeedLevel(SPEED_LEVEL_1); UART_SendString("SPEED 65%\r\n"); break;
      case 'x': Car_SetSpeedLevel(SPEED_LEVEL_2); UART_SendString("SPEED 80%\r\n"); break;
      case 'c': Car_SetSpeedLevel(SPEED_LEVEL_3); UART_SendString("SPEED 98%\r\n"); break;
      case 'q': Car_Stop();     UART_SendString("STOP\r\n"); break;
      case 'n': LED_On();       UART_SendString("LED ON\r\n");  break;
      case 'f': LED_Off(); Car_Stop(); UART_SendString("LED OFF\r\n"); break;
      default: break;
    }

    key_ready = 0U;
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1U);  /* ③ 处理完再开接收 */
  }
}
```

三个细节：

- **先处理超时，再处理命令**：如果转向刚好结束、同时又有新命令，先把转向状态收尾，再执行新命令，状态不会乱；
- **回传字符串是阻塞发送**：9600 波特率下 5~10 个字节约 5~10 ms，可以接受；此时接收本来就是暂停的，不会丢命令；
- **最后才重新挂接收**：保证一个命令的“动作 + 回传”全部完成之前，不会开始收下一个字符。

## 3. 小车移动逻辑

### 3.1 电机抽象层

#### 占空比设置

[main.c:494-511](Core/Src/main.c#L494-L511)：

```c
static void Motor_SetSpeeds(uint8_t left_percent, uint8_t right_percent)
{
  uint32_t period = __HAL_TIM_GET_AUTORELOAD(&htim3) + 1U;  /* 3600 */

  if (left_percent  > 100U) left_percent  = 100U;
  if (right_percent > 100U) right_percent = 100U;

  __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, (period * left_percent)  / 100U);
  __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_2, (period * right_percent) / 100U);
}
```

几个考虑：

- **不写死 3600**，而是从 `ARR` 读 `period = ARR + 1`。以后改 PWM 频率（改 ARR）时，百分比接口不用跟着改；
- **100% 时 CCR = 3600 > ARR = 3599**，PWM1 模式输出恒高，电机全速；0% 时 CCR = 0，输出恒低；
- **左右独立**：`Motor_SetSpeeds()` 是差速转向的基础，`Motor_SetSpeed()` 只是它的“两边相同”的包装。

#### 方向电平

[main.c:526-559](Core/Src/main.c#L526-L559)：

| 函数 | forward=1（车体前进） | forward=0（车体后退） |
| ---- | --------------------- | --------------------- |
| `Motor_SetLeft` | IN1=1，IN2=0 | IN1=0，IN2=1 |
| `Motor_SetRight` | IN3=0，IN4=1（`MOTOR_B_INVERT=1` 时） | IN3=1，IN4=0（`MOTOR_B_INVERT=1` 时） |

右电机多了一行：

```c
uint8_t fwd = (uint8_t)(forward ^ (uint8_t)MOTOR_B_INVERT);
```

这是**镜像安装的 XOR 技巧**：

- 小车左右电机通常对装，同样的 IN 电平会让两个电机相对车体转向相反；
- 把“右电机是否镜像”抽象成一个宏 `MOTOR_B_INVERT`，代码里所有上层逻辑仍然用“forward=车体前进”的语义；
- `MOTOR_B_INVERT=1` 时，`Motor_SetRight(1)` 实际输出 IN3=0、IN4=1；宏为 0 时输出相反；
- 如果实车按 `w` 原地打转，把宏改成 0，或对调右电机两根线（两种方法只改一个）。

#### PWM 频率

TIM3：`PSC=0`、`ARR=3599`，TIM3 时钟 72 MHz：

```
f = 72 000 000 / (3599 + 1) = 20 kHz
```

20 kHz 高于人耳听觉上限，电机不会啸叫，也在 L298N 的推荐范围内。

### 3.2 状态变量

[main.c:78-88](Core/Src/main.c#L78-L88)：

| 变量 | 含义 |
| ---- | ---- |
| `speed_percent` | 当前速度档位（65/80/98），默认 65 |
| `car_moving` | 1 = 正在前进或后退 |
| `car_dir` | 0 = 停，1 = 前进，2 = 后退 |
| `turning` | 1 = 正在执行 10° 转向 |
| `turn_inner_left` | 行进转向时内履带是左还是右 |
| `turn_end_tick` | 转向结束的 SysTick 时刻 |

把“方向”“是否行驶”“是否转向”“速度档”拆成独立变量，而不是一个大的状态枚举，好处是：

- `Car_SetSpeedLevel()` 只需要判断 `turning/car_moving`，不用枚举所有组合；
- 转向时 `car_dir` 保持不变，所以“转向不打断前进/后退”天然成立；
- 新增动作（例如以后加原地旋转、加减速）时不用重写状态机。

### 3.3 前进与后退

[main.c:564-587](Core/Src/main.c#L564-L587)：

```c
static void Car_Forward(void)
{
  turning = 0U;              /* 取消可能正在进行的转向 */
  car_dir = 1U;
  Motor_SetSpeed(0U);        /* 先降速，避免带载换向 */
  Motor_SetLeft(1U);
  Motor_SetRight(1U);
  Motor_SetSpeed(speed_percent);
  car_moving = 1U;
}
```

`Car_Backward()` 对称：`car_dir = 2`，左右都 `Motor_SetLeft/Right(0)`（反转），再恢复速度。

**为什么先 `Motor_SetSpeed(0)` 再换向？**

- 如果车正在高速前进，直接反转 IN1/IN2，L298N 会经历“全压反接制动”，电流冲击大，机械冲击也大；
- 先降占空比到 0，再改方向，最后升到目标速度，相当于一次“软换向”。

### 3.4 停车

[main.c:674-684](Core/Src/main.c#L674-L684)：

```c
Motor_SetSpeed(0U);
IN1 = IN2 = IN3 = IN4 = 0;
car_moving = 0; car_dir = 0; turning = 0;
```

四个方向脚全部拉低 + 占空比 0，L298N 两路输出关闭，电机**自由滑行**（coast）。

> 如果希望“刹车”而不是滑行，可以把同一路的 IN1/IN2 同时拉高（L298N 短接电机两端），但履带车急刹容易打滑，这里选择滑行停车。

### 3.5 10° 转向：两种模式

转向入口是 [main.c:631-669](Core/Src/main.c#L631-L669) 的 `Car_Turn(char cmd)`，根据 `car_dir` 分两种模式。

#### 模式 A：停车时原地转

```c
if (car_dir == 0U)
{
  if (cmd == 'a') { Motor_SetLeft(1U); Motor_SetRight(0U); }  /* 左正/右反 */
  else            { Motor_SetLeft(0U); Motor_SetRight(1U); }  /* 左反/右正 */

  Motor_SetSpeeds(65, 65);
  turning = 1U;
  turn_end_tick = HAL_GetTick() + TURN_PIVOT_MS;  /* 100 ms */
  return;
}
```

- 两履带**反向**，绕车体中心原地旋转；
- 固定 65% 占空比（履带阻力大，不能太低）；
- 100 ms 后由主循环停车。

计算依据（代码注释里也有）：

```
履带中心距 B ≈ 245 − 33 = 212 mm
驱动轮直径 D = 39 mm
65% 占空比有效转速约 165 r/min
v = π × 0.039 × 165 / 60 ≈ 0.337 m/s
ω = 2v / B ≈ 3.18 rad/s ≈ 182 °/s
10° 理论 ≈ 55 ms，加起步死区/滑移取 100 ms
```

#### 模式 B：行进中差速转（不打断前进/后退）

```c
if (cmd == 'a')
{
  turn_inner_left = (car_dir == 2U) ? 1U : 0U;
}
else
{
  turn_inner_left = (car_dir == 1U) ? 1U : 0U;
}

Car_ApplyTurnSpeeds();
turning = 1U;
turn_end_tick = HAL_GetTick() + TURN_MOVING_MS;  /* 240 ms */
```

**关键：没有调用 `Motor_SetSpeed(0)`，也没有改 IN1~IN4**，方向脚保持前进/后退状态，只改左右 PWM。

`Car_ApplyTurnSpeeds()`（[main.c:595-622](Core/Src/main.c#L595-L622)）：

```c
outer = min(speed_percent + TURN_OUTER_BOOST, 100);  /* +15 */
inner = outer - TURN_INNER_DROP;                     /* −30 */

left = right = outer;
if (turn_inner_left) left = inner; else right = inner;
Motor_SetSpeeds(left, right);
```

实际取值：

| 档位 | 外履带 | 内履带 | 平均速度 | 差速 |
| ---- | ------ | ------ | -------- | ---- |
| 65% | 80% | 50% | 65% | 30 |
| 80% | 95% | 65% | 80% | 30 |
| 98% | 100% | 70% | 85% | 30 |

这里有一个重要的**调参故事**：

- 早期版本是“外履带 = 当前档位，内履带 = 当前档位 − 30”，65 档时内履带只有 **35%**；
- 实车测试发现：左转正常，右转非常慢；
- 原因是履带阻力大，35% 可能低于某一侧电机的起转阈值，内履带被拖着走甚至停转，车要拖着一侧停转的履带转向，阻力很大；
- 现在把两条履带**整体抬高 15 个点**，差速仍是 30 点（转 10° 的时间不用改），但内履带最低也有 50%，能持续滚动；
- 同时 65/80 档的平均速度仍是 65/80，转向时不会明显减速。

这是一个“用软件补偿机械不对称”的例子：不改变差速，只抬高工作点。

#### 内/外履带方向一致性

`turn_inner_left` 的取值保证：**同一个命令，无论前进还是后退，车身旋转方向一致**。

| 命令 | 前进时内履带 | 后退时内履带 | 旋转方向（与原地转向一致） |
| ---- | ------------ | ------------ | -------------------------- |
| `a` | 右 | 左 | 原地 a：左正/右反 |
| `d` | 左 | 右 | 原地 d：左反/右正 |

推导思路：

- 前进时，内履带慢 → 车体向该侧转；
- 后退时，同样的“内侧慢”会让车体向相反方向转，所以后退时要把内/外履带对调；
- 这样 `a` 永远对应同一种旋转方向，`d` 对应相反方向，和原地转向保持一致。

#### 非阻塞定时（巧思）

转向没有用 `HAL_Delay()`，而是：

```c
turning = 1U;
turn_end_tick = HAL_GetTick() + TURN_MOVING_MS;
```

主循环每次进来检查：

```c
if (turning && (int32_t)(HAL_GetTick() - turn_end_tick) >= 0)
{
  if (car_dir == 0U) Car_Stop();
  else { turning = 0U; Motor_SetSpeed(speed_percent); }
}
```

好处：

- 转向期间串口仍然能收命令，`q`/`f` 可以立即停车，不会被 `HAL_Delay` 卡住；
- `w`/`s` 可以在转向中途直接切换方向；
- 用 `(int32_t)(now - end) >= 0` 而不是 `now >= end`，兼容 `HAL_GetTick()` 的 32 位溢出回绕。

### 3.6 速度档位

档位宏（[main.c:34-37](Core/Src/main.c#L34-L37)）：

```c
#define SPEED_LEVEL_1 65U
#define SPEED_LEVEL_2 80U
#define SPEED_LEVEL_3 98U
```

对应 TIM3 的 CCR（`ARR+1 = 3600`）：

| 档位 | 占空比 | CCR |
| ---- | ------ | --- |
| z | 65% | 2340 |
| x | 80% | 2880 |
| c | 98% | 3528 |

`Car_SetSpeedLevel()`（[main.c:692-712](Core/Src/main.c#L692-L712)）：

```c
speed_percent = percent;

if (turning)
{
  if (car_dir != 0U) Car_ApplyTurnSpeeds();  /* 行进转向中：保持差速，外履带跟新档 */
}
else if (car_moving)
{
  Motor_SetSpeed(speed_percent);            /* 直行中：两履带同时改 */
}
/* 停车时只记录，下次 w/s 生效 */
```

细节：

- **直行中改档立即生效**，不用停车；
- **行进转向中改档**会重新计算外/内履带，差速仍保持 30 点，转向角度基本不变；
- **停车时改档只记录**，避免在停止状态下突然给 PWM；
- 98% 而不是 100%，留一点余量，避免电源/驱动饱和和电流过大。

## 4. 参数设置一览

| 宏 | 默认值 | 作用 | 调整建议 |
| -- | ------ | ---- | -------- |
| `SPEED_LEVEL_1/2/3` | 65 / 80 / 98 | 三档速度 | 按场地和负载调整，建议不超过 98 |
| `TURN_DUTY_PERCENT` | 65 | 原地转向占空比 | 履带阻力大时不要低于 60 |
| `TURN_PIVOT_MS` | 100 | 原地转 10° 时间 | 实测角度后按比例缩放 |
| `TURN_INNER_DROP` | 30 | 行进转向内外履带差速 | 越大转得越快，但内履带易停转 |
| `TURN_OUTER_BOOST` | 15 | 行进转向两履带整体抬高 | 一側仍慢时可加大到 20 |
| `TURN_MOVING_MS` | 240 | 行进中转 10° 时间 | 实测角度后按比例缩放 |
| `MOTOR_B_INVERT` | 1 | 右电机镜像 | `w` 原地打转时改 0 或对调右电机线 |

PWM：TIM3，20 kHz；串口：USART1，9600 8N1。

## 5. 函数封装与调用关系

```
USART1_IRQHandler
   └─ HAL_UART_IRQHandler
        └─ HAL_UART_RxCpltCallback  (main.c:119)
             └─ key_char / key_ready  (单槽邮箱)

main while(1)
   ├─ 转向超时检查 (main.c:213)
   └─ switch(key_char)
        ├─ Car_Forward  ── Motor_SetSpeed / Motor_SetLeft / Motor_SetRight
        ├─ Car_Backward ── 同上
        ├─ Car_Turn ───── Car_ApplyTurnSpeeds ── Motor_SetSpeeds
        ├─ Car_Stop ───── Motor_SetSpeed + GPIO
        ├─ Car_SetSpeedLevel ── Motor_SetSpeed / Car_ApplyTurnSpeeds
        └─ LED_On / LED_Off + UART_SendString
```

| 函数 | 职责 | 是否直接操作硬件 |
| ---- | ---- | ---------------- |
| `HAL_UART_RxCpltCallback` | 收字符、白名单、置邮箱 | 否（只写变量） |
| `HAL_UART_ErrorCallback` | 清 ORE、恢复接收 | 是（宏清标志） |
| `UART_SendString` | 阻塞发送回传字符串 | 是（HAL_UART_Transmit） |
| `Motor_SetSpeeds` | 左右独立占空比 | 是（CCR1/CCR2） |
| `Motor_SetLeft/Right` | 方向电平 | 是（GPIO） |
| `Car_Forward/Backward` | 直行 | 通过电机层 |
| `Car_ApplyTurnSpeeds` | 行进差速 | 通过电机层 |
| `Car_Turn` | 原地/行进转 10° | 通过电机层 |
| `Car_Stop` | 停车 + 清状态 | 通过电机层 |
| `Car_SetSpeedLevel` | 档位切换 | 通过电机层 |

## 6. 巧思总结

1. **单字符协议 + 白名单**
   不需要组帧、缓冲区、`strcmp`；`\r\n` 自动忽略，手机串口助手怎么发都不会误动作。

2. **单槽邮箱 + 暂停接收**
   `key_char/key_ready` 相当于深度 1 的消息队列；处理期间不挂接收，天然防止覆盖，不需要环形缓冲。

3. **非阻塞转向定时**
   用 `HAL_GetTick()` 记录结束时刻，主循环轮询；转向期间仍能响应 `q`/`f`/`w`/`s`，比 `HAL_Delay` 安全。

4. **状态解耦**
   `car_dir`、`car_moving`、`turning`、`speed_percent` 各管一件事；转向不改变 `car_dir`，所以“转向不打断前进/后退”是结构上保证的，而不是靠额外判断。

5. **差速转向的两种模式统一入口**
   `Car_Turn()` 内部按 `car_dir` 分流：停车原地转、行进差速转；上层命令只发 `'a'`/`'d'`，不关心当前状态。

6. **内外履带方向一致性**
   `turn_inner_left` 根据 `car_dir` 取反，保证同一命令在前进/后退时旋转方向一致。

7. **整体抬高工作点**
   行进转向不再把内履带压到 35%，而是整体 +15、差速不变；既避免内履带停转拖死，又保持平均速度和 10° 时间，属于“机械不对称的软件补偿”。

8. **先降速再换向**
   避免全压反接的电流和机械冲击。

9. **百分比接口 + 从 ARR 取周期**
   `Motor_SetSpeeds(0~100)` 与 PWM 频率解耦，改 ARR 不需要改调用处。

10. **右电机镜像用 XOR 宏**
    上层永远用“车体前进”的语义，硬件差异集中在一个宏里。

11. **用户代码全部在 USER CODE 区**
    重新用 CubeMX 生成不会丢代码。

## 7. 典型时序

```
手机发 'w'
  → USART1 中断 → 回调 → key_char='w', key_ready=1
  → 主循环 switch → Car_Forward()
  → 回传 "FWD\r\n"
  → key_ready=0，重新挂接收

手机发 'a'（此时正在前进）
  → Car_Turn('a') → turn_inner_left=0 → Car_ApplyTurnSpeeds()
  → 左 80% / 右 50%（65 档），方向脚不变
  → 240 ms 后主循环检测超时
  → turning=0，Motor_SetSpeed(65) 恢复两履带同速，继续前进

手机发 'q'
  → Car_Stop()：PWM=0，IN1~IN4=0，car_dir/car_moving/turning 清零
```

## 8. 标定与调试建议

- **原地 10°**：发 `a`，量实际角度 θ，`TURN_PIVOT_MS = 100 × 10 / θ`；
- **行进中 10°**：先 `w` 再 `a`，量角度 θ，`TURN_MOVING_MS = 240 × 10 / θ`；
- **某一侧转向仍慢**：先把 `TURN_OUTER_BOOST` 从 15 加到 20；仍不行则检查履带张紧、电机、L298N 通道；
- **直行跑偏**：开环双电机本身有差异，可后续接编码器做闭环；
- **转向方向反了**：原地转向改 `Car_Turn()` 里 `'a'`/`'d'` 两段的 IN 电平；行进转向改 `turn_inner_left` 的取值；
- **回传乱码**：确认串口助手 9600 8N1，且共地。

---

## 9. 可扩展方向

- **编码器闭环**：两路编码器接 PB6/PB7、PB8/PB9，TIM4/TIM2 编码器模式，按轮径/履带中心距计算机身角度，做位置环或 PID；
- **多字符协议**：如果以后命令变多，可以恢复“缓冲区 + 结束符”的解析，或者加长度/校验；
- **DMA 接收**：高波特率或高频命令时，用 DMA + IDLE 中断替代单字节中断；
- **加减速曲线**：在 `Car_SetSpeedLevel()` 里做斜坡，减少履带打滑和电流冲击；
- **命令回传优化**：把 `UART_SendString` 改成非阻塞（DMA/中断发送），避免阻塞主循环。

---

如有新的硬件参数（编码器 PPR、履带实际中心距、整车重量等），可以进一步把 10° 从“开环标定”升级为“编码器计数闭环”，精度会明显提高。
